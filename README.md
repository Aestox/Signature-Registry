# Реестр электронных подписей

Веб-приложение для ведения реестра сроков действия электронных подписей и
машиночитаемых доверенностей (МЧД). Публичная часть показывает только
разрешённые сведения и не отображает уволенных сотрудников. Администратор
может просматривать закрытые данные и управлять записями. Публичная
регистрация отключена; журналы действий не создаются.

Английская версия этого руководства: [README.en.md](README.en.md).

## Возможности

- Публичный реестр с поиском и пагинацией по 10 записей.
- Административная панель с входом, CRUD-записями, поиском и такой же
  пагинацией.
- Информация о сроках действия ЭП и МЧД с выделением истёкших и скорых сроков.
- Интерфейс на русском и английском языках: `/ru` и `/en`. Адрес `/`
  перенаправляет на английскую версию.
- Дополнительные поля записи, видимые только администраторам.

## Стек

- **Next.js App Router**, **React**, **TypeScript**
- **Tailwind CSS 4** и компоненты в стиле **shadcn/ui** на базе **Radix UI**
- **PostgreSQL** — основная база данных
- **Drizzle ORM** — типизированный доступ к данным; **Drizzle Kit** —
  создание и применение миграций
- **Better Auth** — вход администратора и управление сессией
- **next-intl** — локализация интерфейса

## Требования

- Node.js 20.9 или новее и npm
- Docker с Docker Compose для локального PostgreSQL
- Для внешней базы данных — доступный PostgreSQL; локальный Compose в этом
  случае не нужен

Все команды ниже выполняются из корня репозитория.

## Настройка и локальный запуск

1. Создайте локальный файл окружения:

   ```powershell
   Copy-Item .env.example .env
   ```

   Откройте `.env` и задайте собственные значения:

   | Переменная | Назначение |
   | --- | --- |
   | `DATABASE_URL` | Строка подключения приложения к PostgreSQL |
   | `DIRECT_URL` | Необязательная прямая или session-pooler строка для миграций Drizzle; по умолчанию используется `DATABASE_URL` |
   | `POSTGRES_DB` | Имя базы для локального Docker Compose |
   | `POSTGRES_USER` | Пользователь локальной базы |
   | `POSTGRES_PASSWORD` | Пароль локальной базы; он должен совпадать с паролем в `DATABASE_URL` |
   | `BETTER_AUTH_SECRET` | Секрет Better Auth; используйте случайное значение не короче 32 символов |
   | `BETTER_AUTH_URL` | Базовый URL приложения, локально обычно `http://localhost:3000` |
   | `ADMIN_NAME` | Имя первого администратора |
   | `ADMIN_EMAIL` | Email первого администратора |
   | `ADMIN_PASSWORD` | Пароль первого администратора, минимум 14 символов |

   Если пароль базы содержит специальные символы, закодируйте их для URL в
   `DATABASE_URL`. Не добавляйте `.env` в Git и не используйте локальные
   секреты в production.

2. Запустите локальный PostgreSQL и установите зависимости:

   ```powershell
   docker compose up -d postgres
   npm ci
   ```

   Compose публикует PostgreSQL только на `127.0.0.1:5432` и хранит данные в
   отдельном Docker volume.

3. Примените миграции:

   ```powershell
   npm run db:migrate
   ```

4. Необязательно: добавьте вымышленные данные для локальной разработки:

   ```powershell
   npm run db:seed-demo
   ```

   Скрипт создаёт 21 демонстрационную запись, безопасно ограничен локальными
   адресами PostgreSQL и идемпотентен: повторный запуск не добавляет дубликаты.
   Не запускайте его для production-базы.

5. Создайте первого администратора:

   ```powershell
   npm run admin:create
   ```

   Задайте `ADMIN_NAME`, `ADMIN_EMAIL` и `ADMIN_PASSWORD` до запуска команды.
   Повторное создание уже существующего пользователя завершится ошибкой.

6. Запустите приложение:

   ```powershell
   npm run dev
   ```

   Откройте `http://localhost:3000` — по умолчанию приложение перенаправит на
   `/en`. Страница входа администратора: `/en/admin/login` или
   `/ru/admin/login`.

Для остановки локальной базы используйте `docker compose down`. Не добавляйте
флаг `-v`, если хотите сохранить данные volume.

## PostgreSQL и Drizzle

Схема базы объявлена в `src/lib/db/schema.ts`, подключение приложения
настраивается в `src/lib/db/client.ts`, а `drizzle.config.ts` указывает Drizzle
Kit на схему, каталог миграций `drizzle/` и `DIRECT_URL` (или `DATABASE_URL`,
если `DIRECT_URL` не задан). Схема содержит
реестр и таблицы Better Auth.

Обычный процесс изменения структуры базы:

1. Измените типизированную схему в `src/lib/db/schema.ts`.
2. Создайте SQL-миграцию:

   ```powershell
   npm run db:generate
   ```

3. Проверьте сгенерированный SQL в `drizzle/`, затем примените миграцию:

   ```powershell
   npm run db:migrate
   ```

4. Добавьте новую миграцию в Git вместе с изменением схемы. Не изменяйте уже
   применённые миграции: создавайте следующую миграцию.

Для внешнего PostgreSQL, включая управляемый сервис, укажите его строку в
`DATABASE_URL`, задайте корректный `BETTER_AUTH_URL` и выполните миграции перед
запуском приложения. В production секреты задаются в настройках окружения
хостинга, а не в `.env`. Не открывайте базу данных в публичный интернет.

## Supabase

Supabase можно использовать как управляемый PostgreSQL без перехода на
Supabase Auth: приложение подключается к базе на серверной стороне через
Drizzle, а аутентификацию администратора по-прежнему обслуживает Better Auth.
Supabase SDK, публичный API-ключ и URL проекта приложению не нужны.

1. Создайте проект Supabase и скопируйте строки подключения на странице
   **Connect**.
2. Для serverless-хостинга используйте строку **transaction pooler** как
   `DATABASE_URL`. Клиент PostgreSQL отключает prepared statements для
   совместимости с этим режимом.
3. Задайте `DIRECT_URL` как строку прямого подключения для миграций Drizzle.
   Если среда не поддерживает сеть IPv6, используйте session pooler. В
   локальной разработке оставьте `DIRECT_URL` пустым.
4. Настройте `BETTER_AUTH_URL` и `BETTER_AUTH_SECRET` для развёрнутого
   приложения, затем выполните миграции и создайте администратора.

Используйте значения из панели Supabase, не добавляйте пароли или строки
подключения в Git и не передавайте `DATABASE_URL` клиентскому коду. Подробнее:
[Drizzle с Supabase](https://supabase.com/docs/guides/database/drizzle) и
[подключение к PostgreSQL](https://supabase.com/docs/guides/database/connecting-to-postgres).

## Демо-данные и импорт JSON

`npm run db:seed-demo` предназначен только для локального PostgreSQL.
Демонстрационные записи синтетические и не содержат реальных данных.

Для импорта записей подготовьте JSON-массив в формате, который принимает
скрипт `scripts/import-registry.ts`, например:

```json
[
  {
    "id": 1,
    "nameFull": "Пример записи",
    "email": null,
    "post": null,
    "depo": null,
    "certificate_type": null,
    "serial_number": null,
    "certificate_status": null,
    "release_date": null,
    "end_date": null,
    "certification_center": null,
    "platform": null,
    "mchd": null,
    "release_date_mchd": null,
    "end_date_mchd": null,
    "contract": null,
    "place_contur_extern": 0,
    "fired": 0,
    "notes": null
  }
]
```

Затем запустите:

```powershell
npm run db:import -- "C:\secure-path\registry.json"
```

Имена полей должны соответствовать формату, который разбирает
`scripts/import-registry.ts`. Даты задаются как `YYYY-MM-DD` или `null`;
логические поля принимают `0`/`1` или `false`/`true`. Импорт сохраняет ID и не
перезаписывает существующие записи. Импортируются только записи реестра.
Храните файл вне репозитория и удалите его после проверки импорта.

## Полезные команды

| Команда | Назначение |
| --- | --- |
| `npm run dev` | Локальная разработка |
| `npm run build` | Production-сборка |
| `npm run start` | Запуск production-сборки |
| `npm run lint` | ESLint |
| `npx tsc --noEmit` | Проверка TypeScript |
| `npm run db:generate` | Создать миграцию из изменений схемы |
| `npm run db:migrate` | Применить миграции |
| `npm run db:seed-demo` | Добавить локальные демонстрационные записи |
| `npm run admin:create` | Создать администратора из переменных окружения |
| `npm run db:import -- <путь>` | Импортировать записи из JSON |

## Основные каталоги

- `src/app/[locale]` — публичные и административные страницы с локалью в URL
- `src/components` — таблицы, формы, поиск и элементы интерфейса
- `src/lib/db` — Drizzle-подключение и схема PostgreSQL
- `src/i18n` и `messages` — настройка локализации и переводы
- `drizzle` — SQL-миграции и журнал миграций
- `scripts` — создание администратора, демонстрационные данные и импорт

Добавляйте строки интерфейса одновременно в `messages/ru.json` и
`messages/en.json`.
